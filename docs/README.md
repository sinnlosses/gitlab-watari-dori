# ドキュメント索引

使い方・設定書式・CI セットアップはリポジトリルートの README、開発時の約束事の一覧は
リポジトリルートの CLAUDE 向けガイドにある。このディレクトリには**その先の詳細**を置く。

| ファイル                                       | 何が書いてあるか                                                       | いつ読むか                                             |
| ---------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------ |
| [`requirements.md`](./requirements.md)         | 何を作るか / 作らないか、判定順序、非機能要件                          | 機能を足す前、スコープに迷ったとき                     |
| [`architecture.md`](./architecture.md)         | 全体の流れ、各ディレクトリの責務、置き場の早見表、設計判断、既知の制約 | 新しいコードの置き場に迷ったとき、既存の形を変えるとき |
| [`coding-standards.md`](./coding-standards.md) | 各規約の理由と例外（`as`・型・環境変数・エラー処理・コメント・テスト） | 規約の意図を確かめたいとき、レビュー時                 |
| [`glossary.md`](./glossary.md)                 | ドメイン用語とコード上の識別子の対応                                   | 用語の意味が曖昧なとき、命名を決めるとき               |
| [`workflow.md`](./workflow.md)                 | `develop/` を使ったタスク運用のうち、このプロジェクト固有の部分        | タスクを進めるとき                                     |
| [`smoke-test.md`](./smoke-test.md)             | 実機 GitLab での確認手順（5 パス）                                     | gitbeaker 更新後、判定ロジックを変えたとき             |

## 置き場のルール

| 種類                       | 置き場           |
| -------------------------- | ---------------- |
| 調査記録（一次情報の出典） | `docs/research/` |
| 設計判断の記録（ADR）      | `docs/adr/`      |
| 完了タスク・過去の進捗     | `docs/history/`  |

これらは**必要になった時点で作る**。空のディレクトリは置かない。`docs/history/` は
`/next-task` のアーカイブ処理が自動で作るので、手で掘らない。

`docs/history/` 配下は**当時の記述をそのまま残す**アーカイブで、この索引には載せない。
